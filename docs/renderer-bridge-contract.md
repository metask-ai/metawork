# MetaWork Renderer Bridge 合同

> 状态：`metawork.renderer-bridge` 固定 revision 1
> 日期：2026-08-07

顶层模块职责见 [MetaWork 高层架构](architecture.md)。本文件是 Renderer 与 Product 之间 command、event、Snapshot、连接与运输语义的唯一架构真源；具体源码目录见 [工程结构与所有权](project-structure.md)，持续验收入口见 [验证规范](validation.md)。

## 1. Bridge 定位

Bridge 是 Renderer 与 Application 之间的唯一通信边界，承运两类 surface。产品命令面：验证调用来源与启动窗口 identity、严格解码 payload、把合法输入转换为产品命令、dispatch 给 Product 中对应 owner、编码 typed result，并通过 Snapshot/Event 运输发布产品投影；Bridge 不决定 Task 是否可以运行、Workspace 是否有效、Agent 是否应取消、credential 是否可以替换或历史如何持久化，这些判断必须由 Product 内对应 owner 完成。受限平台 capability 面：只承运 window-chrome bootstrap capability，当前封闭枚举为 `metawork.host.windowChrome.connect / sync / beginDrag / control / disconnect` 五个 command，dispatch 给 Application 执行，原生窗口行为与真实状态由 Native SDK/OS 拥有。两面共用同一 transport、origin policy 与 source/window authority，不共用数据面；新增平台面 command 必须与 capability seam 同级登记（identity、SDK 缺口、删除条件），不因该面已存在而豁免。

Task binding projection 只运输 `epoch + availability + provider + model + executionGeneration + unavailableReason`。`unavailableReason` 当前只有 `runtime_detached`，表示恢复历史没有进程内 Session/ExecutionConfig；Task projection 不包含 account identity、API Key selection/metadata、Model Connection identity/generation、credential locator 或完整 ExecutionConfig，也不得用当前 Account/Model Connection projection 为历史 Task 补写这些字段。

Bridge 的唯一产品数据面由具体 `Dispatcher` 内部的 `ProductDelivery` 统一拥有：connection generation、revision retry/timer、snapshot identity 和 snapshot transport storage 都不再存放在 `app.zig`。Dispatcher 通过明确的 `*Workbench` 同步生成 snapshot；Application 只注入 Native emit/timer/dialog/window-chrome/main-thread capability，并组织 Bridge、Product、Agent 与 Native SDK 的顶层 shutdown；Agent event 的产品投影和固定终态 drain 屏障由 Workbench 执行，Application 只安排 main-loop 调用。

`hidden_inset_tall` 的 System WebView window chrome 是独立于 ProductDelivery connection 的受限 Host bootstrap capability。browser-side Bridge boundary 直接使用既有 `window.zero.invoke` transport 执行 `metawork.host.windowChrome.connect/sync/control/disconnect`，并且只有 Host 返回 `livePointerDrag = true` 时才可执行 `beginDrag`。`connect` 返回 document generation、可用 top band/safe insets、caption-button bounds、`rendererControls`、`maximized` 与 live-pointer capability；`sync` 只接受 viewport 和最多一个 top-band candidate 加 32 个 contained exclusions；`beginDrag` 只接受同 generation 的 Web client coordinate；`control` 只接受同 generation 的 `minimize | toggle_maximize | close`；`disconnect` 精确撤销同一 generation。所有响应在 browser-side Bridge runtime decode 后才写入 CSS variables/document dataset，React product component 只绘制 declarative controls，不消费 DTO、不调用 transport、不维护窗口状态。

Bridge policy 先约束 origin，Dispatcher 再校验 Application 注入的单一启动窗口 identity、document generation、payload 上界与主线程；Application capability 不能接收 HWND、活动窗口猜测、任意 action、platform 或独立 state query。document generation 与 source-window authority 只归 Dispatcher：`connect` 在 document attach 时建立一次 generation，`sync`、`beginDrag`、`control` 与 `disconnect` 只能使用该 generation；resize、layout 或 command failure 都不得隐式 reconnect 或轮换 generation。browser-side Bridge 通过 Native SDK 正式 `window.zero.on("resize")` 事件、`ResizeObserver` 与 `MutationObserver` 把最新 viewport/region snapshot 合并到同一个 animation-frame scheduler，并保证最多一个 `sync` in flight；`sync` 以完整候选集事务式替换 live regions，失败输入不得造成半更新，也不得清除仍有效的 control environment 或 session。Windows `beginDrag` 把 Renderer 坐标只当作格式与候选一致性输入；Application capability 必须以当前逻辑主鼠标键、实际 OS 光标、光标下 HWND 的 root identity、native hit、DPI 和最新 region snapshot 重新授权，再把手势交给系统 caption move loop。一次 `beginDrag` 失败只结束当前手势，只有 `sync` 失败才使 Renderer 的 drag geometry gate 失效。`minimize` 使用 Native SDK Runtime API，SDK 0.8.0 尚未提供的 maximize/restore、user-close 和 maximized state 由独立登记的 `system_webview_window_controls` seam 补齐，user-close 必须进入 `close_policy = hide` 的平台用户关闭路径。macOS `beginDrag` 仅补足 SDK 对 live pointer event 的要求并保留系统交通灯。拖动循环、resize、close policy、托盘和真实状态始终由 Native SDK/OS 拥有。该 bootstrap capability 不建立第二产品数据面，也不得扩展为通用窗口 API、Native SDK adapter、第二窗口 owner 或任意 action facade；Native SDK 官方能力经平台验收可用后，必须在 revision 1 内逐项原位替换对应 seam，并同步收口不再需要的 command、allowlist、DTO 和测试。automation 只能驱动真实产品路径，不注册测试专用协议。

## 2. ProductDelivery 与 Snapshot transport

Host view snapshot 使用 Bridge `Dispatcher` 内部 `ProductDelivery` 独占的 64 MiB 有界存储，不受 Bridge 单次 1 MiB result 上限反向约束。该容量覆盖 512 KiB Task projection、最大 Account API Key/model catalog、bounded Model Connection projection、Workspace/Task Skill catalog 结构、JSON 最坏转义和全部结构上界。Dispatcher 同时拥有 callback gate、workspace grants、handler registry 和 `*Workbench`，产品 command 的 decode、authority、domain call 与 response encode 不再经过 `app.zig`。Workbench writer 只能在同步调用期间借用这块 output buffer；返回后 Bridge 独占 encoded bytes，禁止保存 Workbench borrowed view。Renderer 通过带 snapshot identity 的 256 KiB 分块读取完成 resync；begin 写入前先使旧 descriptor 失效，序列化失败后旧 identity 必须保持 stale，不能继续读取已被部分覆盖的 store。revision 通知和 snapshot 拉取分别保留 pending/retry 状态，瞬时发送或读取失败不能把旧视图标记为最新。revision retry 同时受 attempt 和 deadline 预算约束，耗尽或 retry timer 不可用时当前 event connection fail closed，但不终止后台 Agent Run。新 event generation 建立时会使旧 snapshot descriptor 失效；Renderer 若仍持有旧 generation Promise，必须在旧 Promise 退出后继续完成新 generation 的实际 resync，不能把等待旧 Promise 误判为同步成功。Bridge 异步保留的 payload 必须自有；Application 在 shutdown 时先 stop Bridge ingress，在 Native platform loop 上确认同步 handler quiescence，再关闭 delivery connection、取消 timer，并 detach Workbench；随后依次收口 Account coordinator、Workbench 与 Agent，完成 terminal drain/lifecycle sync，最后才独立释放 delivery buffers。

## 3. Renderer Bridge wire contract

Host 与 Renderer 随同一应用包原子发布，不承担旧 Renderer/新 Host 或新 Renderer/旧 Host 的兼容。bootstrap 必须拒绝合同 identity 或经用户批准后出现的 revision 错配；固定 revision 策略下，`connect` 无法通过 revision 数字识别同 revision 的陈旧开发产物。严格 command catalog 和 payload decoder 只能在实际命令或结构差异被触及时失败，不能检测纯 wire 语义错配。此类错配属于 unsupported development state，必须通过 clean rebuild、清理缓存或重新安装恢复；原子打包用于降低发生概率，不构成 runtime compatibility guarantee。Renderer Bridge contract 覆盖全部 product command、event 和 snapshot wire surface；它与产品版本、AgentCore ABI、bundle manifest schema 相互独立。

Renderer Bridge 使用独立合同身份 `metawork.renderer-bridge`，快速开发阶段固定 revision 为 `1`。Host 与 Renderer 随同一应用包原子发布，任何 command、event、payload 字段或 wire 语义变化都直接原地 hard cut，不为临时合同形态递增 revision、不维护兼容层，也不在 snapshot 内维护第二个局部版本。`contractRevision` 仍精确匹配，用于拒绝非当前固定标识，但不承诺识别同 revision 的开发产物错配。任何合同类版本标识的变更都必须先得到用户显式同意；对本文件即包括 Renderer Bridge revision。

## File preview command (v1)

`metawork.files.preview` accepts exactly `{ "fileReferenceId": string }`. The
Renderer never submits a filesystem path, URI, shell command, or AgentCore
handle. The Host resolves the opaque id against Workbench history, rechecks
workspace containment and no-follow file access, and returns a bounded UTF-8
preview:

```json
{
  "state": "ready | truncated | missing | restricted | unsupported | error",
  "id": "file-id",
  "title": "main.zig",
  "displayPath": "src/main.zig",
  "language": "zig",
  "content": "...",
  "truncated": false,
  "range": null
}
```

Line and column values in `range` are canonical decimal strings in both the
`metawork.files.preview` response and Snapshot `tools[].fileRefs[]` entries.
The Host converts AgentCore's typed numeric positions at this wire boundary;
Renderer decoders do not accept a second numeric representation. Preview
content is bounded by the Workbench limits and is never persisted as a second
product state; the file reference metadata is persisted with Task history.

当前 `metawork.tasks.run` 只有 `input.kind = text | skill` 的 tagged payload，旧 `prompt` 不兼容；Skill input 精确为 `{ kind, skillId, catalogRevision, selectionRevision, argumentValues }`。`tasks.create` 必须携带 `workspace = { kind: "automatic" } | { kind: "manual", workspaceId, expectedWorkspaceEpoch }`、nullable `expectedSkillCatalogRevision` 和 nullable `expectedSkillSelectionRevision`；Text 两个 revision 均为 `null`，Skill 两者均非空，混合状态 fail closed。Bridge 与 Workbench 直接使用同一组 `manual | automatic` admission 语义；混合、缺字段或未知 kind 的 payload 一律 fail closed。不存在 `workspaces.select` 命令或 Snapshot 级 selected Workspace；Manual 选择只属于 Renderer New task draft，真正的 epoch、authorization 与 recent order 在 `tasks.create(manual)` 事务中校验和提交。`automaticWorkspaces` 只声明新 Automatic Workspace 的分配能力；capability 不可用时，已恢复的 Automatic Workspace 与 owning Task 历史仍可出现在 snapshot 中。Skill 没有 `runSkill` 第二入口。Workspace/Task catalog、typed Run history 和 Skill terminal cause 只从 Workbench snapshot 发布；显式 catalog refresh 也只通过 Bridge 调用 Workbench transaction，Bridge 不持有 catalog lease、不解析 slash、不读取 Skill body。

`metawork.skills.setEnabled` 是 revision 1 内的原地 hard cut command。payload 精确为 `{ scope, workspaceId, expectedWorkspaceEpoch, skillId, state, expectedCatalogRevision, expectedSelectionRevision }`：`scope = personal` 时两个 Workspace 字段必须为 null 且 `state = enabled | disabled`；`scope = project` 时两个 Workspace 字段必须是已授权 Manual Workspace 的 canonical identity，且 `state = inherit | enabled | disabled`。skill 必须属于对应 current catalog。成功返回 `{ applied: true, selectionRevision, reason: null }`，业务拒绝返回 `{ applied: false, selectionRevision: null, reason }`；非法 shape、越权或非 canonical identity 仍 fail closed。Snapshot 中每个 `skillCatalog` 含 nullable `selectionRevision`，每个 descriptor 含 effective `enabled`；ready/degraded catalog 的两份 revision 均非空，其他状态均为 null。`skillManagement` 含 `enablementAvailability`，asset 含 nullable effective `enabled`、nullable `enablementState`、`canSetEnabled` 与 nullable `selectionRevision`；Personal 的 state 只取 enabled/disabled，Project 的 state 可以 inherit。管理 authority 与 enablement authority 分离，能够精确映射当前 catalog member 的 external asset 也可启停，但仍不可因此获得导出、重新导入或卸载 authority。

已有 Task 的模型切换使用独立的 `metawork.tasks.selectModel` command，payload 精确为 `{ taskId, expectedModel, expectedCatalogGeneration, selectionId }`，结果为 `{ accepted, taskId, model, reason }`。`expectedModel` 是 Task 当前 binding 的 compare-and-swap 事实；它不是 Account 默认模型，也不携带 credential。`selectionId` 必须来自当前 Account model catalog，catalog generation 不匹配或模型不再存在时返回 `stale_catalog`。模型切换不 bump Task `binding.epoch`，不改变 pinned `executionGeneration`；已有 Run 继续使用其自己的历史模型。活跃 Run 期间的选择只进入 Host runtime pending，下一次 Run admission 前应用，pending 不进入 persistence 或 Snapshot wire。

Conversation recovery 使用同一 revision 1 数据面上的 `metawork.tasks.restore`。payload 精确为 `{ taskId, expectedBindingEpoch }`，结果精确为 `{ accepted, taskId, attemptId, reason }`；`attemptId` 仅在 accepted 时为 canonical decimal `u64`，reason 仅在 rejected 时取 `binding_changed | task_unavailable | recovery_unavailable | capacity_reached | shutting_down`。Bridge 只负责严格 decode、Task authority 与结果 encode，不读取 checkpoint、不决定 eligibility、不调用 Agent。该 command 可由用户 Retry 或发送路径内部调用；accepted 只表示恢复 job 已入队，Renderer 必须等待同一 Task 的 canonical snapshot 确认 attachment 后才能提交 `tasks.run`。结果不确定或 Renderer timeout 时只能 resync snapshot，不能自动重放。

Pending permission projection 使用 `{ requestId, runId, order, redacted, kind: "permission", tool, args, availableChoices }`。`availableChoices` 由 AgentCore 当前 request 的 `responses[]` 计算；Session choice 只有在 candidate 存在时才可发布，当前 revision 8 的 candidate scope 为 `exact_arguments`。Renderer 只能提交 `deny_once | deny_session | allow_once | allow_session` 中实际出现在 `availableChoices` 的 choice；不得提交 `policy_generation`、candidate `rule_id` 或原始 AgentCore response。Agent 从 pending request 回填这些 ABI 字段并完成最终校验。

Permission occurrence 在 `uiHistory` 中额外携带 `agentRequestId` 与 nullable `permission` 摘要。摘要字段固定为 `requestId`、`matchedRuleId`、`toolNamespace`、`toolName`、`toolBinding`、`decision`、`source`、`policyGeneration`、`usedSessionRule`、`callbackOutcome`；它只包含非 secret identifier 和脱敏决策结果，不包含原始参数、credential 或可重放 response。Restore 后 Task snapshot 的 `restorePermission` 仅是本次 restore 的 `{ restoredRules, invalidatedRules }` 运行健康投影，不能被 Renderer 当作本地 grant cache。

根 `capabilities.conversationRecovery` 当前为 true。每个 Task 延续唯一 continuation 模型：`continuationAvailable` 表示现在可启动下一 Run，`continuationUnavailableReason` 精确取 `session_poisoned | event_projection_failure | closing | closed | task_archived | session_recovery_required | session_recovery_in_progress | session_recovery_failed | persistence_unavailable | checkpoint_unavailable | execution_mismatch | workspace_unavailable | authority_unavailable | runtime_unavailable` 或 null，`continuationRecoveryAvailable` 表示当前 snapshot 下允许显式提交 restore。active operation 可取 `restore`。Decoder 必须联合校验这些字段：attached 可继续态不能同时声称可恢复；required/failed 只有在全部 Host gate 成立时才可发布 recovery available；in-progress 必须对应 restore operation；closed/archived/closing、普通 Run/compact 或 capability=false 时不得发布恢复动作。不得新增并行的 `task.recovery` 状态对象。

Skill management 使用同一 revision 1 数据面发布 bounded preview/detail/projection 与 typed import/export/reimport/uninstall mutation；command catalog、Zig DTO、TypeScript runtime decoder、snapshot fixture 和 automation 必须完全一致，不建立第二 transport 或局部 revision。

MCP 管理使用同一 revision 1 snapshot 与 command 数据面，原地 hard cut 为 transport-discriminated catalog：`metawork.mcp.createStdioServer`、`metawork.mcp.createHttpServer`、`metawork.mcp.updateStdioConnection`、`metawork.mcp.updateHttpConnection`、`metawork.mcp.renameServer`、`metawork.mcp.approveConnection`、`metawork.mcp.captureSecret`、`metawork.mcp.authorizeOAuth`、`metawork.mcp.cancelAuthorization`、`metawork.mcp.setServerEnabled`、`metawork.mcp.setAllowedTools`、`metawork.mcp.removeServer`、`metawork.mcp.testConnection` 与 `metawork.mcp.refreshCatalog`；不得暴露 generic upsert、secret-bearing payload 或第二 OAuth callback data plane。所有 server command 携带 canonical decimal `expectedDesiredGeneration` 和目标 `serverId`（create 除外）；create/update 的 shared fields 为 bounded `displayName`、`negotiation = automatic | modern_only | compat_only` 与 `timeoutMs`。STDIO payload 额外携带 `command`、ordered public-text `arguments`、nullable `cwd` 和唯一 `environmentNames`，不提供 shell string、credential argv 或 environment value。HTTP payload 额外携带严格 endpoint、`authMode = none | static | oauth`、唯一 `headerNames`，以及 OAuth registration plan。payload 不接受 header value、client secret、token 或 OAuth metadata。Host 生成 identity/namespace；create 保存为 enabled、approved、空 allowlist，update 在同一 target 中为新连接生成 approval fingerprint，并使不兼容的 OAuth consent 失效。

`approveConnection` 只服务 schema 1 迁移留下的 legacy unapproved server；普通 Add/Replace 不经过该 command。`captureSecret` 只携带 slot identity，由 Host secure-capture capability 直接写 credential store；该能力不可用时返回 typed `capability_unavailable`，绝不回退为 Renderer secret input。`authorizeOAuth` 只对 approved Streamable HTTP OAuth server 启动全局唯一、server-bound operation，并继续保留独立的 Host consent。`testConnection` 使用 `McpServerIdentity` payload，结果精确为 `started | busy | stale_generation | needs_authentication | rejected | unavailable`；started 表示 Host 已启动一个隔离候选 Runtime 的真实 activation，不表示测试已成功。完成状态只经 snapshot/notification 发布，不返回 raw catalog 或 diagnostic。`refreshCatalog` payload 为空，只刷新当前正式 Runtime catalog，不应用 pending connection configuration 或隐式启动 OAuth。

根 `capabilities` 必须包含 boolean `mcpManagement`、`mcpConnectionApproval`、`mcpSecretCapture` 与 `mcpOAuth`；后三者只声明对应 Host effect capability，不代表某个 server 已批准、已有 credential 或 OAuth ready。根 `mcp` 必须精确包含 `availability`、`managementHealth`、`operation`、`authorizationOperation`、`desiredGeneration`、`runtimeAlignment`、`redacted` 与 `servers`：`availability = unavailable | ready | degraded`；`managementHealth = unavailable | ready | recovery_required | outcome_unknown`；`operation = idle | saving | refreshing`；`authorizationOperation = { kind: "idle" } | { kind: "discovering" | "awaiting_consent" | "registering" | "awaiting_browser" | "exchanging" | "refreshing" | "cancelling", serverId, operationId }`；generation 是 canonical decimal `u64` wire string 或 null；alignment 为 `current | restart_required | unknown`。没有可信 canonical desired 时 generation 必须为 null、alignment unknown、servers 为空且 authorization operation idle；空 registry 但 management ready 是正常状态。`mcpManagement = false` 时发布 fail-closed baseline，所有 MCP effect capability 同时为 false。任何不变量不满足都使 Renderer snapshot decode fail closed。

每个 server 使用唯一 opaque `id` 与唯一 `namespace`，并精确包含 `displayName`、`transport = stdio | streamable_http`、`authMode = none | static | oauth`、`negotiation = automatic | modern_only | compat_only`、正整数 `timeoutMs`、nullable typed `connection`、`approvalStatus`、`authorizationStatus`、`desiredEnabled`、`runtimeStatus`、`newTaskAccess`、已清洗的 `safeDiagnostic`、`connectionTest` 与 `tools`。`connectionTest` 精确为 `{ status: untested | testing | connected | failed, toolCount, issueCount }`，只存在于当前进程 projection；配置 mutation 清除旧结果，Host 重启后回到 untested。`connection` 对有效、未被 credential scrub 的 STDIO 精确发布 command、ordered arguments、nullable cwd 与 environment name/status；对 Streamable HTTP 精确发布 endpoint、header name/status、registration kind、用户提供的 client id、token endpoint auth method 与 client-secret status。配置无效或已触发 credential scrub 时 `connection = null`，Renderer 不得猜测或允许盲目替换。

Host 将 Desired Registry 的完整非敏感 typed connection、authorization operation、Runtime Manifest disposition、Agent opaque Activation health 与 Admission Authority 合成为 projection。environment/header value、credential locator、client secret、token/code/PKCE、动态注册所得内部材料、raw OAuth metadata、raw diagnostic、schema body、fingerprint 和 AgentCore handle 不进入 projection；Renderer 不直接解码或镜像 AgentCore MCP schema。`redacted` 只表示 Host 确实移除了可发布文本。Runtime-alignment unknown 或 persistence outcome unknown 时不得发布 last-known desired 伪装 canonical state。

Renderer 的 Slash Resolver 只在 Composer 首 token 处理 `/` 手势。单一 Command registry 当前只由 `App` action controller 复用既有 New task 动作；Command 原文在 Renderer 消费，不产生 Run。Skill 候选只来自当前 Workspace/Task catalog projection，选择后形成带稳定 identity、pinned revision 与 positional arguments 的 tagged draft，再沿唯一 `tasks.run` 路径提交。Command/Skill 同名时裸名称归 Command，Skill 使用 `/skill:name`；Renderer 不读取 Skill body、物理路径或 policy。

Account API/model selection payload 携带脱敏 selection identifier、`expectedCatalogGeneration` 与 `expectedExecutionGeneration`。Bridge 只校验 identifier 的 wire 边界并把 generation 严格解析为 `u64`；单值 `"0"` 合法，前导零、非数字与 overflow 非法。generation 是否匹配以及 identifier 是否属于当前发布的 Account catalog 由 Product 判断，Bridge 不读取产品 `AccountView`。

Model Connection mutation 使用同一 revision 1 数据面上的 typed `create | update | remove | test | selectDefault` commands。create/update 只接受 bounded display name、明确 provider、规范化前的 endpoint 和 model metadata；credential 通过独立 Host-owned secure capture，不进入 Bridge payload。每个 command 携带 opaque `connectionId`（create 除外）与 `expectedConnectionGeneration`，Host 负责 endpoint/provider/model membership 校验、credential 状态和 generation replacement；test 只返回 started/accepted typed result，完成结果经 snapshot/event 的独立 `testStatus = untested | testing | connected | failed` 发布。`state = configuring | ready | disabled` 表示当前 generation readiness，不得用一次失败重测把已 ready generation 或已安装 default execution 降级。`metawork.account.activateMetask` 只接受 expected Metask catalog/execution generation；Host 成功重建 Metask execution 后才原子清除 durable custom default，失败时继续保留原连接。根 `capabilities` 必须精确包含 boolean `modelConnectionManagement`、`modelConnectionSecretCapture` 与 `modelConnectionTest`；`account` 精确发布 `metaskExecutionGeneration`、active `executionGeneration`、`modelConnections` 和 `selectedModelConnectionId`，后者是当前 custom execution 的连接 identity，不能由 Renderer 用第一个 ready connection 或 model id 反推。Renderer 不得把连接字段拼成 `tasks.run` payload，也不得把连接测试 candidate 当作正式 Task binding。

`connect` 是 product delivery 的 bootstrap 边界。Host 必须在合同身份与 revision 校验成功后才建立 `ProductDelivery` connection；既有 `requireWindow()` 门禁随后统一保护 Account、Task、event 和 snapshot 产品路径。协商前只允许显式列出的无状态 bootstrap/smoke 命令，不得读取或修改产品状态。合同不匹配返回 typed terminal bootstrap error，Renderer 不把它当作瞬时断线重试。

Zig/TypeScript 的 identity、revision 和完整 command catalog 必须精确一致，`app.zon` allowlist 不得缺项或多项；Host serializer → TypeScript decoder 与 TypeScript bootstrap payload → Host decoder 必须有跨语言 fixture/行为测试。Renderer 内同一 wire enum 的 TypeScript type 与 runtime decoder 必须消费同一值目录，不能维护彼此独立的 union 与 allowlist；Host 新增产品 cause 时，serializer、Renderer 值目录、文案和跨语言 fixture 必须在同一变更中收齐。Renderer 始终 runtime decode Host payload；malformed payload 或 decoder/serializer contract mismatch 一律进入 fail-closed view-sync failure，不能猜测字段或静默降级。
