# MetaWork Renderer Bridge 合同

> 状态：`metawork.renderer-bridge` 固定 revision 1
> 日期：2026-08-07

顶层模块职责见 [MetaWork 高层架构](architecture.md)。本文件是 Renderer 与 Application 之间 command、event、Snapshot、连接与运输语义的唯一架构真源；具体源码目录见 [工程结构与所有权](project-structure.md)，持续验收入口见 [验证规范](validation.md)。

## 1. Bridge 定位

Bridge 是 Renderer 与 Application 之间的入站协议边界。它只负责验证调用来源与启动窗口 identity、严格解码 payload、把合法输入转换为产品命令、调用 Application、编码 typed result，并通过 Snapshot/Event 运输发布产品投影。Bridge 不决定 Task 是否可以运行、Workspace 是否有效、Agent 是否应取消、credential 是否可以替换或历史如何持久化；这些判断必须由 Application 内对应 owner 完成。

Bridge 的唯一产品数据面由具体 `Dispatcher` 内部的 `ProductDelivery` 统一拥有：connection generation、revision retry/timer、snapshot identity 和 snapshot transport storage 都不再存放在 `app.zig`。Dispatcher 通过明确的 `*Workbench` 同步生成 snapshot；Desktop Host composition role 只注入 Native emit/timer/dialog/window-chrome/main-thread capability，并在顶层按 Bridge → Application → Native SDK 的依赖顺序组织 shutdown；Application 内部的 owner 收口与事件屏障仍由 App coordinator 执行。

`hidden_inset_tall` 的 System WebView window chrome 是独立于 ProductDelivery connection 的受限 Host bootstrap capability。browser-side Bridge boundary 直接使用既有 `window.zero.invoke` transport 执行 `metawork.host.windowChrome.connect/sync/control/disconnect`，并且只有 Host 返回 `livePointerDrag = true` 时才可执行 `beginDrag`。`connect` 返回 document generation、可用 top band/safe insets、caption-button bounds、`rendererControls`、`maximized` 与 live-pointer capability；`sync` 只接受 viewport 和最多一个 top-band candidate 加 32 个 contained exclusions；`beginDrag` 只接受同 generation 的 Web client coordinate；`control` 只接受同 generation 的 `minimize | toggle_maximize | close`；`disconnect` 精确撤销同一 generation。所有响应在 browser-side Bridge runtime decode 后才写入 CSS variables/document dataset，React product component 只绘制 declarative controls，不消费 DTO、不调用 transport、不维护窗口状态。

Bridge policy 先约束 origin，Dispatcher 再校验 Desktop Host-owned 单一启动窗口 identity、document generation、payload 上界与主线程；Host seam 不能接收 HWND、活动窗口猜测、任意 action、platform 或独立 state query。document generation 与 source-window authority 只归 Dispatcher：`connect` 在 document attach 时建立一次 generation，`sync`、`beginDrag`、`control` 与 `disconnect` 只能使用该 generation；resize、layout 或 command failure 都不得隐式 reconnect 或轮换 generation。browser-side Bridge 通过 Native SDK 正式 `window.zero.on("resize")` 事件、`ResizeObserver` 与 `MutationObserver` 把最新 viewport/region snapshot 合并到同一个 animation-frame scheduler，并保证最多一个 `sync` in flight；`sync` 以完整候选集事务式替换 live regions，失败输入不得造成半更新，也不得清除仍有效的 control environment 或 session。Windows 把镜像区域转成 native non-client hit test；`minimize` 使用 Native SDK Runtime API，SDK 0.8.0 尚未提供的 maximize/restore、user-close 和 maximized state 由独立登记的 `system_webview_window_controls` seam 补齐，user-close 必须进入 `close_policy = hide` 的平台用户关闭路径。macOS `beginDrag` 仅补足 SDK 对 live pointer event 的要求并保留系统交通灯。拖动循环、resize、close policy、托盘和真实状态始终由 Native SDK/OS 拥有。该 bootstrap capability 不建立第二产品数据面，也不得扩展为通用窗口 API、Native SDK adapter、第二窗口 owner 或任意 action facade；Native SDK 官方能力经平台验收可用后，必须在 revision 1 内逐项原地替换对应 seam，并同步收口不再需要的 command、allowlist、DTO 和测试。automation 只能驱动真实产品路径，不注册测试专用协议。

## 2. ProductDelivery 与 Snapshot transport

Host view snapshot 使用 Bridge `Dispatcher` 内部 `ProductDelivery` 独占的 16 MiB 有界存储，不受 Bridge 单次 1 MiB result 上限反向约束。该容量覆盖 512 KiB Task projection、最大 Account API Key/model catalog、Workspace/Task Skill catalog 结构、JSON 最坏转义和全部结构上界。Dispatcher 同时拥有 callback gate、workspace grants、handler registry 和 `*Workbench`，产品 command 的 decode、authority、domain call 与 response encode 不再经过 `app.zig`。Workbench writer 只能在同步调用期间借用这块 output buffer；返回后 Bridge 独占 encoded bytes，禁止保存 Workbench borrowed view。Renderer 通过带 snapshot identity 的 256 KiB 分块读取完成 resync；begin 写入前先使旧 descriptor 失效，序列化失败后旧 identity 必须保持 stale，不能继续读取已被部分覆盖的 store。revision 通知和 snapshot 拉取分别保留 pending/retry 状态，瞬时发送或读取失败不能把旧视图标记为最新。revision retry 同时受 attempt 和 deadline 预算约束，耗尽或 retry timer 不可用时当前 event connection fail closed，但不终止后台 Agent Run。新 event generation 建立时会使旧 snapshot descriptor 失效；Renderer 若仍持有旧 generation Promise，必须在旧 Promise 退出后继续完成新 generation 的实际 resync，不能把等待旧 Promise 误判为同步成功。Bridge 异步保留的 payload 必须自有；Desktop Host composition role 在 shutdown 时先 stop Bridge ingress、关闭 delivery connection 并取消 timer，在 Native platform loop 上确认同步 handler quiescence，然后调用 Application 的收口路径、detach Workbench，最后才独立释放 delivery buffers。

## 3. Renderer Bridge wire contract

Host 与 Renderer 随同一应用包原子发布，不承担旧 Renderer/新 Host 或新 Renderer/旧 Host 的兼容。bootstrap 必须拒绝合同 identity 或经用户批准后出现的 revision 错配；固定 revision 策略下，`connect` 无法通过 revision 数字识别同 revision 的陈旧开发产物。严格 command catalog 和 payload decoder 只能在实际命令或结构差异被触及时失败，不能检测纯 wire 语义错配。此类错配属于 unsupported development state，必须通过 clean rebuild、清理缓存或重新安装恢复；原子打包用于降低发生概率，不构成 runtime compatibility guarantee。Renderer Bridge contract 覆盖全部 product command、event 和 snapshot wire surface；它与产品版本、AgentCore ABI、bundle manifest schema 相互独立。

Renderer Bridge 使用独立合同身份 `metawork.renderer-bridge`，快速开发阶段固定 revision 为 `1`。Host 与 Renderer 随同一应用包原子发布，任何 command、event、payload 字段或 wire 语义变化都直接原地 hard cut，不为临时合同形态递增 revision、不维护兼容层，也不在 snapshot 内维护第二个局部版本。`contractRevision` 仍精确匹配，用于拒绝非当前固定标识，但不承诺识别同 revision 的开发产物错配。任何合同类版本标识的变更都必须先得到用户显式同意；对本文件即包括 Renderer Bridge revision。

当前 `metawork.tasks.run` 只有 `input.kind = text | skill` 的 tagged payload，旧 `prompt` 不兼容；`tasks.create` 必须携带 `workspace = { kind: "automatic" } | { kind: "manual", workspaceId, expectedWorkspaceEpoch }` 和 nullable `expectedSkillCatalogRevision`。Bridge 与 Workbench 直接使用同一组 `manual | automatic` admission 语义；混合、缺字段或未知 kind 的 payload 一律 fail closed。不存在 `workspaces.select` 命令或 Snapshot 级 selected Workspace；Manual 选择只属于 Renderer New task draft，真正的 epoch、authorization 与 recent order 在 `tasks.create(manual)` 事务中校验和提交。`automaticWorkspaces` 只声明新 Automatic Workspace 的分配能力；capability 不可用时，已恢复的 Automatic Workspace 与 owning Task 历史仍可出现在 snapshot 中。Skill 没有 `runSkill` 第二入口。Workspace/Task catalog、typed Run history 和 Skill terminal cause 只从 Workbench snapshot 发布；显式 catalog refresh 也只通过 Bridge 调用 Workbench transaction，Bridge 不持有 catalog lease、不解析 slash、不读取 Skill body。

Skill management 使用同一 revision 1 数据面发布 bounded preview/detail/projection 与 typed import/export/reimport/uninstall mutation；command catalog、Zig DTO、TypeScript runtime decoder、snapshot fixture 和 automation 必须完全一致，不建立第二 transport 或局部 revision。

MCP 管理使用同一 revision 1 snapshot 与 command 数据面。完整 command catalog 增加 `metawork.mcp.createHttpServer`、`metawork.mcp.renameServer`、`metawork.mcp.setServerEnabled`、`metawork.mcp.setAllowedTools`、`metawork.mcp.removeServer` 与 `metawork.mcp.refreshCatalog`，不得暴露 generic upsert。前五个 registry mutation 都携带 canonical decimal `expectedDesiredGeneration`；server mutation 额外携带 opaque `serverId`，rename 携带 `displayName`，enable 携带 boolean `enabled`，allowlist 携带有界且唯一的 canonical `toolNames`。create 只携带 `displayName` 与 endpoint，由 Host 生成 identity/namespace 并创建默认 disabled、空 allowlist 的无认证 Streamable HTTP server；endpoint 只允许 HTTPS 或精确 loopback HTTP，禁止 userinfo、query、fragment、header、credential 和 OAuth 输入。refresh payload 为空，只刷新当前 Runtime catalog，不读取或应用 pending connection configuration。result 与错误必须 typed；stale generation、rejected、saved、saved recovery required 和 indeterminate 不能折叠成普通成功，indeterminate 不返回猜测的 desired generation。

根 `capabilities` 必须包含 boolean `mcpManagement`；它只表示上述 typed management contract 与 strict projection 是否接通，不与 registry 是否为空、Runtime availability 或 management health 做等值判断。根 `mcp` 必须精确包含 `availability`、`managementHealth`、`operation`、`desiredGeneration`、`runtimeAlignment`、`redacted` 与 `servers`：`availability = unavailable | ready | degraded` 表示当前 Runtime/catalog；`managementHealth = unavailable | ready | recovery_required | outcome_unknown` 表示 Desired Registry 管理边界；`operation = idle | saving | refreshing`；`desiredGeneration` 是 canonical decimal `u64` wire string 或 null；`runtimeAlignment = current | restart_required | unknown`。没有可信 canonical desired 时 generation 必须为 null、alignment 必须为 unknown，且 servers 必须为空；空 registry 但 management ready 是非 unavailable 的正常可管理状态。`mcpManagement = false` 时必须精确发布 `{ availability: "unavailable", managementHealth: "unavailable", operation: "idle", desiredGeneration: null, runtimeAlignment: "unknown", redacted: false, servers: [] }`，不得发布可执行动作；capability 为 true 但 health frozen 时页面保持可达、动作禁用。任何不变量不满足都使 Renderer snapshot decode fail closed。

每个 server 使用唯一 opaque `id` 与唯一 `namespace`，并精确包含 `displayName`、`transport = stdio | streamable_http`、`desiredEnabled`、`runtimeStatus`、`newTaskAccess`、已清洗的 `safeDiagnostic` 与 `tools`。`runtimeStatus = not_loaded | ready | disabled | needs_authentication | unreachable | invalid_catalog`；`newTaskAccess = available | not_allowed | restart_required | unavailable`。每个 tool 以 server 内唯一 canonical `name` 标识，并包含 `discovered`、`desiredAllowed` 与 `availableToNewTasks`；tool 集合是当前安全 catalog 与 desired allowlist 的有界 union，保留 configured-but-not-discovered tool 以便用户收窄陈旧配置，但不得从 registry 猜测 schema、描述或 runtime health。`availableToNewTasks` 只有在当前 Admission Authority 实际包含该 selector 时才为 true；Runtime ready、desired allowed 或 catalog discovered 任何单一事实都不能推导它。

Host 将 Desired Registry、Runtime Manifest 的安全 disposition、Agent opaque Activation health 与 Admission Authority 合成为该 projection。command、arguments、environment、完整 URL、header、credential、OAuth 数据、raw diagnostic、schema body、Runtime/absence fingerprint 和 AgentCore handle 不进入 projection；Renderer 不直接解码或镜像 AgentCore MCP JSON schema。`redacted` 只表示 Host 确实移除了可发布文本，不能作为 Renderer 重建秘密配置的提示。Runtime-alignment unknown 或 persistence outcome unknown 时不得发布 last-known desired 伪装 canonical state。

Renderer 的 Slash Resolver 只在 Composer 首 token 处理 `/` 手势。单一 Command registry 当前只由 `App` action controller 复用既有 New task 动作；Command 原文在 Renderer 消费，不产生 Run。Skill 候选只来自当前 Workspace/Task catalog projection，选择后形成带稳定 identity、pinned revision 与 positional arguments 的 tagged draft，再沿唯一 `tasks.run` 路径提交。Command/Skill 同名时裸名称归 Command，Skill 使用 `/skill:name`；Renderer 不读取 Skill body、物理路径或 policy。

Account API/model selection payload 携带脱敏 selection identifier、`expectedCatalogGeneration` 与 `expectedExecutionGeneration`。Bridge 只校验 identifier 的 wire 边界并把 generation 严格解析为 `u64`；单值 `"0"` 合法，前导零、非数字与 overflow 非法。generation 是否匹配以及 identifier 是否属于当前发布的 Account catalog 由 Application 判断，Bridge 不读取产品 `AccountView`。

`connect` 是 product delivery 的 bootstrap 边界。Host 必须在合同身份与 revision 校验成功后才建立 `ProductDelivery` connection；既有 `requireWindow()` 门禁随后统一保护 Account、Task、event 和 snapshot 产品路径。协商前只允许显式列出的无状态 bootstrap/smoke 命令，不得读取或修改产品状态。合同不匹配返回 typed terminal bootstrap error，Renderer 不把它当作瞬时断线重试。

Zig/TypeScript 的 identity、revision 和完整 command catalog 必须精确一致，`app.zon` allowlist 不得缺项或多项；Host serializer → TypeScript decoder 与 TypeScript bootstrap payload → Host decoder 必须有跨语言 fixture/行为测试。Renderer 内同一 wire enum 的 TypeScript type 与 runtime decoder 必须消费同一值目录，不能维护彼此独立的 union 与 allowlist；Host 新增产品 cause 时，serializer、Renderer 值目录、文案和跨语言 fixture 必须在同一变更中收齐。Renderer 始终 runtime decode Host payload；malformed payload 或 decoder/serializer contract mismatch 一律进入 fail-closed view-sync failure，不能猜测字段或静默降级。
