# SQLite 产品历史接入验收

日期：2026-10-27。分支：`feat/sqlite-storage`。用户已授权正式接入 SQLite，并解除 #12 / #25 的累计数量限制。

## 已完成

- Application 使用 `workbench-history.sqlite`；旧 framed 文件只作单向导入源及迁移材料，不双写。临时库校验、关闭后发布；较新 schema 禁止写入及显式恢复替换。
- Product schema 保存独立记录；比较完整候选与上次确认的行摘要，只向 SQL 提交变化和删除。变化与 witness 同事务，unknown 读回并同步确认，不重放业务操作。后续完整候选补齐此前失败或跳过的变化。
- Task 独立分配、集合增长；Run / Compact 在 worker lease 静止后增长。恢复按实际数量分配，审批历史不再覆盖最旧八条。自动 Workspace 和 Skill catalog 注册集合同步扩容。
- 历史正文预算与 catalog 投影预算分离；历史 Task 不消耗 live Session 名额。
- 首次获知凭据清洗当前 SQL、WAL 和旧迁移源；重复借用不重复维护。冻结候选携带安全代次，旧代次不能在凭据释放后重新写入。冻结缓冲释放时清零。

## 验收覆盖

- 100 个 Task × 256 个 Run：累计输入与回答超过旧 1.5 MiB 预算，冻结候选超过旧 16 MiB 文件上限，保存并关闭后重新载入全部 25,600 个 Run 和已读回执。
- 真实 Product 生命周期：同一 Task 连续 21 个 Run；仅一个 Session 名额时连续创建 100 个 Task，分别覆盖手动与自动 Workspace。
- 写失败后一次无关提交补写、提交回执丢失确认、恢复发布结果未知、部分 quarantine 中断、维护连接故障后重开、未知 schema 拒绝恢复、opaque 记录保留、凭据轮换和旧安全代次拒绝。
- 正式 Native 测试图 233/233 步骤成功，1,446 项测试通过、7 项跳过；架构边界测试 32/32 通过，Zig 格式检查与 `git diff --check` 通过。
- 当前 Windows MSVC 目标的正式 Native Debug 桌面产物构建通过，产物为 `zig-out/bin/metawork.exe`；没有把构建成功记作人工桌面验收。
- 同轮完整 Node suite：984 项，976 通过、8 跳过、0 失败；Renderer typecheck 通过。该次聚合命令随后在 Native 阶段失败；修复后使用正式 Native 入口单独复验，不把前一次聚合命令记作成功。

## 保留的限制

解除的是累计 16 Run / 50 Task 固定槽位限制，不承诺无限容量。生产历史正文额度为 256 MiB，仍有字段、事务和视图资源边界；正文额度不是进程 RSS 上限。

磁盘写入已经增量化；当前候选冻结、解码及摘要比较仍随全部内存历史增长。原有性能 Gate 与非 ASCII 搜索耗时继续单独保留，本记录不宣称性能验收完成。单事务超出 Storage 额度时明确失败，不拆业务原子组，也未引入后台事务调度器或磁盘历史缓存。

实现提交：`208b5d63`、`433ba900`、`ac96d785`、`3078bf3c`、`839de6c6`；最后的生命周期与安全收口见本记录所属提交。

## 阻塞评审修复与复验

原验收偏重只增不删和小正文，不能证明删除复用、大 Task、积压补写及恢复中途失败可用。以下修复替代此前对这些路径的完成判断；不涉及性能 Gate。

| 发现 | 修复与回归 | 提交 |
| --- | --- | --- |
| 删除后复用 ordinal 导致后续保存失败 | 同一事务先让受影响行让出 ordinal，再 upsert；保留 schema 与唯一约束。覆盖 Task/Workspace 删除、新建、随后保存及重启 | `e0af50ca`，分块配合见 `3df56ac4` |
| SQL 恢复误移动旧 `.store` | 只有正式 SQL 不存在且旧文件是失败导入源时才隔离旧文件；正常 SQL 恢复原字节保留旧源 | `c185d47d` |
| 恢复失败后使用已关闭连接 | close 标记必须重开；提交前检查连接，缺 canonical 的部分恢复保持拒写。覆盖 close 后及 quarantine 后故障、再提交与重试恢复 | `c185d47d` |
| 单 Task 仍受 16 MiB 中转限制 | 中转 record 与整体 handoff 使用同一边界，缓冲不足和永久超限分开处理 | `3df56ac4` |
| 积压/全量恢复超过 batch 额度 | 有界 mutation chunks 共用一个事务及 witness；按实际参数量装块，较大单行直接绑定，批量 upsert/delete 有界分组 | `92e189dc`、`3df56ac4` |
| 凭据拒绝时泄漏编码缓冲 | 检查前建立释放和清零；增长中的编码缓冲同样清零。重复八次拒绝不得调用 writer，测试分配器检查泄漏 | `4144d65f`、`3df56ac4` |
| 旧源清洗失败卡住 SQL unknown | SQL 清洗与旧源维护分别记录；旧源失败保留维护标记及凭据副本，安全 SQL 可继续提交和恢复，修复旧源后才能释放副本 | `8dd6e98e` |
| read-only Task 恢复 OOM 泄漏 | record 创建失败释放已复制 payload；在该分配点注入 OOM，验证分配/释放计数一致 | `4144d65f` |

新增大历史回归使用单 Task、136 个 Run，每个 Run 输入和回答各 128 KiB，累计正文 34 MiB。覆盖失败后一次回执变更带上全部积压、显式恢复、关闭重开和正文/回执完整性。另以 140 条 retained records 覆盖超过 128 条语句的原子保存、失败回滚及删除；Storage 覆盖后块 conflict 回滚前块，以及无效后块不得执行前块。
